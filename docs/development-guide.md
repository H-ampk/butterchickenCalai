# 共同開発ガイド

5人のチームで地域割引SNSアプリを開発するための手順です。

## Issue管理

機能追加や修正は、Issue を作成してから着手します。

Issue には次を書きます。

- 目的
- 作業内容
- 担当領域
- 完了条件

## Pull Request

変更は Pull Request で統合します。Pull Request には次を書きます。

- 関連 Issue
- 変更概要
- 動作確認内容
- 注意事項

原則として、担当者以外がレビューします。マージ前に、その変更で必要なテストを実行します。

## コード管理

- 作業単位は可能な限り小さくする
- 無関係な変更を同じ Pull Request に含めない
- 他メンバーの担当領域を無断で大幅に変更しない
- APIやデータベース構造を変えるときは、関係担当者と調整する
- 依存パッケージを追加するときは、理由を説明する

## ブランチ

`main` は動作確認済みのコードを保持します。原則として `main` へ直接 push しません。作業ブランチは Issue ごとに作ります。

例:

```text
feat/home-page
feat/shop-registration
feat/post-api
feat/map-view
fix/login-error
docs/update-readme
```

## セキュリティ

- `.env` や秘密情報を GitHub に登録しない
- パスワードを平文で保存しない
- 店舗の投稿を編集・削除する処理には、所有権の確認を必要とする
- フロントエンドの表示制御だけで権限制御を完結させない
